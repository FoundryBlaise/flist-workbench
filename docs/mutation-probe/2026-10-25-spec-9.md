# Mutation probe: after spec #9

Run on 2026-10-25 against `spec/9-test-foundation` at f4c5f19 plus the
restore-fixture fix from #19, with the listed tests per mutation
(`probe.py --report`). The eleven sidecar survivors were run again with
`--whole-suite` (787 tests): all eleven still survive, so none of them is
an artefact of the test selection. How to read this: docs/MUTATION_PROBE.md.

The audit's archive figure counted kills by the archive tests only; A11
and A17 were caught by MCP tests it ran separately, and the probe runs
those too. A06 could not be applied in the audit (its find text matched
twice); re-measured on main 77d79c4 with this tool it is killed. The
audit's renderer log was lost, so the R audit column was re-measured on
main 77d79c4; it reproduces the audit's 10 of 23 exactly.

No area lost a kill. Spec #9 did not target the archive gaps; those
belong to specs #2 to #4.

R06, R09 and R15 are also killed now, by the assertions #17 made honest.

**R04** (no follow-up save for edits typed while a save is in flight)
cannot be killed through behaviour as the store stands: every edit arms
its own autosave, so the newer text is saved without the follow-up. The
in-flight test that asserts exactly that ("typing while a save is in
flight ... then saves the newer text") passes with and without the
mutation. Spec #2's fix for the double follow-up flush (one follow-up per
character after an in-flight save, see its comment) makes the follow-up
the only path, and with it this mutation killable. It is listed under #2.

## Fixed along the way

The probe's unmutated baseline failed:
`test_mcp_ops.py::test_extension_pairing_is_read_only` fails whenever it
runs after `test_restore_saved.py` or `test_restore_extension.py`, whose
fixtures paired the extension in module state and never unpaired. The
full suite's alphabetical order hid it. Both fixtures now revoke the
pairing on teardown.
